# Cost Intelligence: Methodology

Module owner: Person 2. Code: `cost_engine/`.

## 1. Cost estimation formula

```
input_cost  = (input_tokens  / 1,000,000) x input_price_per_million
output_cost = (output_tokens / 1,000,000) x output_price_per_million
total_cost  = input_cost + output_cost
```

When `output_tokens` is predicted rather than observed, the result is called **estimated cost**. It is not an invoice: providers may bill differently (caching discounts, batch pricing, tool/reasoning tokens, rounding).

## 2. Pricing architecture

A single JSON registry (`data/pricing.json`) loaded by `pricing.py` into `ModelPricing` records (model, provider, input/output price, context window, quality tier). No price appears elsewhere in code. Prices are updateable via file edit or `upsert_pricing`. **Current values are illustrative and unverified.**

## 3. Dataset

Columns: `prompt_id, model, input_tokens, output_tokens, word_count, sentence_count, task_type, complexity, timestamp, cost, data_source`.

**Source: SYNTHETIC.** Generated by `data/generate_synthetic.py` (5,000 rows, seed 42) from assumed per-task output/input ratios, a per-model verbosity multiplier, and log-normal noise. It is not real usage data. Replace with real logs before drawing conclusions.

## 4. Feature engineering

Numeric: `input_tokens, word_count, sentence_count, complexity (1-5)`. Categorical (one-hot): `task_type, model`. At inference time, if raw text is supplied, word/sentence counts and a keyword-based task type are derived from it. Complexity falls back to a length heuristic. Both the keyword classifier and the heuristic are unvalidated.

## 5. Model selection and training

80/20 train/test split (seed 42). Candidates: naive mean baseline, Linear Regression (simple baseline), Random Forest, Gradient Boosting. The model is selected by 5-fold CV RMSE on the **train** split only; test metrics are reported afterwards and not used for selection. XGBoost was not included.

## 6. Evaluation (synthetic data only)

Held-out test results from the run recorded in `data/artifacts/prediction_metrics.json`:

| Model | MAE | RMSE | R2 |
|---|---|---|---|
| Mean baseline | 294.2 | 553.2 | -0.002 |
| Linear Regression | 207.0 | 400.2 | 0.476 |
| Random Forest (selected) | 135.5 | 305.0 | 0.695 |
| Gradient Boosting | 136.4 | 304.4 | 0.697 |

These numbers only show that tree models recover the non-linear structure *built into the synthetic generator*. They are **not** evidence of accuracy on real LLM traffic. Re-run `python -m cost_engine.prediction` on real data and replace this table.

## 7. Limitations and assumptions

- Output length is inherently noisy; prompts alone cannot fully determine it.
- Token counts are assumed to come from a provider-appropriate tokenizer (Person 1); tokenizers differ between providers.
- Optimization savings (`calculate_savings`) assume only input cost changes.
- Quality tiers used by the recommender are subjective and editable, not benchmark-derived.
- Prices are static between updates and exclude discounts, caching, batch and reasoning-token billing.
